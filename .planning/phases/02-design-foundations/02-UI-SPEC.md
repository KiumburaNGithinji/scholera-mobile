## Spacing Scale

Declared values (all multiples of 4 — Tailwind's default `1 unit = 4px` scale matches):

| Token | Tailwind class | Value | Usage |
|-------|----------------|-------|-------|
| xs | `1` | 4px | Icon-text gaps, dense inline padding |
| sm | `2` | 8px | Compact element spacing, chip internal padding-y |
| md | `3` | 12px | Card internal padding-y (compact rows), button padding-y |
| lg | `4` | 16px | Default element spacing, card padding, list row vertical padding |
| xl | `5` / `6` | 20px / 24px | Section padding, screen horizontal padding (default 16, hero screens 24) |
| 2xl | `8` | 32px | Layout gaps between major sections |
| 3xl | `12` | 48px | Major section breaks, EmptyState vertical breathing room |
| 4xl | `16` | 64px | Page-level top spacing (auth screen hero, splash) |

**Touch target minimum:** 44×44pt (iOS HIG / Android Material). Buttons enforce `min-h-[44px]`. Icon-only ListRow trailing chevron tap target padded to 44px.

**Exceptions:**
- `Skeleton` shimmer block heights are content-shape based (e.g. 16px for body line, 24px for heading line) — these are content tokens, not spacing tokens.
- `EmptyState` icon container is 64×64 (`h-16 w-16`) — fits the 4px scale (16 units × 4px = 64px).

**Pre-populated from:** ui-researcher defaults (`design_contract_questions` section), confirmed against Tailwind default scale (1unit = 0.25rem = 4px in NativeWind).

## Typography

Inter loaded in three weights: 400 (regular), 500 (medium), 600 (semibold). The contract uses **two weights only** — 400 and 600. 500 is loaded but reserved as a fallback for OS body rendering on Android.

| Role | Tailwind class | Size (px) | Weight | Line Height | Usage |
|------|----------------|-----------|--------|-------------|-------|
| Caption | `text-xs` | 12 | 400 | 16 (1.33) | Meta labels, timestamp captions, chip text |
| Body | `text-base` | 16 | 400 | 24 (1.5) | Default body, list row title, paragraph copy, button label |
| Heading | `text-xl` | 20 | 600 | 28 (1.4) | Card titles, section headings, screen subtitle |
| Display | `text-3xl` | 30 | 600 | 36 (1.2) | Screen hero (auth screen, dashboard "Welcome back"), modal titles |

**Total: 4 sizes × 2 weights = 8 type combinations max.** No other type tokens are valid — if a screen needs a different size, the executor escalates to UI-SPEC update, not free-styling.

**Letter-spacing:** Default (0). No tracking adjustments — Inter is already tight.

**Color binding:** Body uses `text-fg-primary`; Caption uses `text-fg-muted`. Heading and Display always inherit `text-fg-primary` unless they're inside a colored surface (e.g. error banner uses `text-destructive-fg`).

**Pre-populated from:** `design-direction.md` ("Inter or system sans with tight hierarchy. Headings have weight, body has breathing room.") + ui-researcher defaults (`recommend 1.5 body, 1.2 heading`).

## Color

Color contract follows the 60/30/10 split. Hex values derived from `design-direction.md` (Claude.ai DNA) and finalized below — these are the canonical values for `theme/tokens.ts`.

### Surface tokens (60/30 — neutral foundation, role-independent)

| Role | Token | Hex | RGB triplet (for CSS var) | Usage |
|------|-------|-----|---------------------------|-------|
| Dominant (60%) | `bg-canvas` | `#FAF9F5` | `250 249 245` | Primary screen background — every screen, every modal backdrop |
| Secondary (30%) | `bg-surface` | `#F5F2EB` | `245 242 235` | Cards, ListRow background on contrasted lists, sheet/modal surface, sticky headers |
| Surface elevated | `bg-surface-elevated` | `#FFFFFF` | `255 255 255` | Optional — only for input fields and the topmost modal layer |
| Foreground primary | `text-fg-primary` | `#2A2622` | `42 38 34` | All body text and headings on canvas/surface |
| Foreground muted | `text-fg-muted` | `#7A736A` | `122 115 106` | Captions, meta, helper text, placeholder |
| Border subtle | `border-border-subtle` | `#E8E2D5` | `232 226 213` | Card borders, list-row dividers, input outlines |

### Role accent tokens (10% — swapped at runtime by `RoleThemeProvider`)

The `--color-accent` CSS var is the single role-aware token. `RoleThemeProvider` injects one of these three triplets into the View tree via NativeWind's `vars()` API. Components consume `text-accent` / `bg-accent` / `border-accent` and stay agnostic to which role is active.

| Role | Hex | RGB triplet | Use cases (THE ONLY places accent appears) |
|------|-----|-------------|--------------------------------------------|
| Admin (steel) | `#64748B` | `100 116 139` | Admin tab bar active icon + label, primary CTA buttons in admin flows, role badge pill, dashboard stat-card highlight border |
| Professor (clay) | `#CC785C` | `204 120 92` | Professor tab bar active state, "Compose" / "Add Module" / "Add Item" buttons, role badge pill, "in progress" coverage status indicator |
| Student (sage) | `#86A17C` | `134 161 124` | Student tab bar active state, "Mark Complete" / progress toggle CTA, role badge pill, student progress chip |

### Semantic colors (role-independent, used sparingly)

| Token | Hex | RGB triplet | Reserved for |
|-------|-----|-------------|--------------|
| `bg-destructive` / `text-destructive` | `#B45447` | `180 84 71` | Sign-out confirmation, destructive button variant. NEVER for errors-as-information (those use ErrorView with neutral surface + accent CTA). |
| `bg-success` / `text-success` | `#5E8A60` | `94 138 96` | "Complete" status indicator on roadmap items only |
| `bg-warning` / `text-warning` | `#C49355` | `196 147 85` | "In progress" status indicator (when role is NOT professor — professor uses accent clay instead) |

### Accent reserved-for list (anti-rainbow rule)

The accent color appears in EXACTLY these places across the app and nowhere else:

1. **Active tab bar item** (icon + label) in the role's tab navigator
2. **Primary CTA buttons** (`Button variant="primary"` — see Primitives below)
3. **Role badge pill** in profile screen and (optionally) in app header
4. **Focus ring** on text inputs and pressable components (`border-accent` on focus)
5. **Stat-card top border or icon** on admin dashboard (subtle 2px top border)
6. **"In progress" status icon** on professor roadmap (clay only — student/admin use semantic warning)
7. **Active chip** when chips have a selected state (e.g. tab pill, filter chip)

NEVER use accent for: body text, all text links (links use `text-fg-primary` underlined), card backgrounds, borders on non-focused elements, error surfaces.

**60/30/10 verification:** On any screen, scan for accent pixels — they should occupy <10% of the visible area. If a screen has more accent than that, something is wrong.

**Pre-populated from:** `design-direction.md` Tokens table (warm cream, deep warm charcoal, clay, steel, sage); RGB triplets sourced from STACK.md § Critical Implementation Patterns § 3 (Role-Aware Theming with NativeWind — `100 116 139`, `204 120 92`, `134 161 124` exactly as documented).

## Shadow / Elevation

Native-feeling, NOT Material elevation. Single shadow token used sparingly — most surfaces rely on the warm border-subtle for separation.

| Token | iOS shadow | Android elevation | Usage |
|-------|------------|-------------------|-------|
| `shadow-card` | `shadow-color: #2A2622, opacity: 0.04, radius: 8, offset: {0, 2}` | `elevation: 2` | Cards on canvas (admin stat tiles, course cards) |

## Component Inventory — The 7 Primitives

All primitives live under `components/ui/`. Each primitive is implemented in TypeScript with strict prop types. Each renders without errors using the tokens declared above. Each uses `forwardRef` where ref-forwarding is meaningful (e.g. inputs).

### 1. `Button`

**Path:** `components/ui/button.tsx`

**Prop signature:**
```typescript
type ButtonVariant = 'primary' | 'secondary' | 'ghost' | 'destructive'
type ButtonSize = 'sm' | 'md' | 'lg'

interface ButtonProps {
  children: React.ReactNode
  onPress?: () => void
  variant?: ButtonVariant            // default: 'primary'
  size?: ButtonSize                  // default: 'md'
  disabled?: boolean                 // visual disabled + onPress no-op
  isPending?: boolean                // shows spinner inline; disables press
  leftIcon?: LucideIcon              // optional lucide icon
  rightIcon?: LucideIcon
  fullWidth?: boolean                // default: false
  accessibilityLabel?: string        // required when children is icon-only
}
```

**Visual states:**

| State | Treatment |
|-------|-----------|
| default (primary) | `bg-accent text-white` + `shadow-sm` + `min-h-[44px]` + `rounded-xl` + `px-4 py-3` |
| default (secondary) | `bg-surface text-fg-primary` + `border border-border-subtle` |
| default (ghost) | `bg-transparent text-accent` + no border |
| default (destructive) | `bg-destructive text-white` |
| hover/pressed | `opacity-80` (RN does not have hover; pressed via `Pressable` `style={({pressed}) => pressed && { opacity: 0.7 }}`) |
| disabled | `opacity-40` + `pointerEvents: 'none'` + visual unchanged |
| isPending | shows `<ActivityIndicator />` inline (color matches text); button label hidden or replaced with "Working…"; disabled while pending |

**Composition tokens:** `text-base font-semibold` (body weight 600 for buttons), `rounded-xl` (radius-md), `min-h-[44px]` (touch target), `flex-row items-center justify-center gap-2`.

**Sizes:**
- `sm` → `min-h-[36px] px-3 py-2 text-sm` (override — only for in-row inline actions)
- `md` → `min-h-[44px] px-4 py-3 text-base` (default)
- `lg` → `min-h-[52px] px-5 py-4 text-base` (auth screen "Sign in")

**Accessibility:** `accessibilityRole="button"`, `accessibilityState={{ disabled, busy: isPending }}`.

### 5. `EmptyState`

**Path:** `components/ui/empty-state.tsx`

**Prop signature:**
```typescript

  icon: LucideIcon                   // required — visual anchor (e.g. Inbox, BookOpen)
  title: string                      // required — short noun phrase ("No announcements yet")
  description?: string               // optional — one-sentence next step
  action?: {
    label: string
    onPress: () => void
  }
}
```

**Visual layout:**

```
[centered, 48px from top]
  [64×64 icon container, bg-surface rounded-full, icon at 24×24 in text-fg-muted]
  [16px gap]
  [title: text-xl font-semibold text-fg-primary]
  [8px gap]
```

**Usage convention (downstream contract for Phases 4-8):**
- Every list screen MUST render `<EmptyState>` when data is empty — never a blank `<View>`, never a single line of text.
- Title pattern: "No {plural noun} yet" (e.g. "No announcements yet", "No modules yet", "No courses enrolled").
- Description pattern: one sentence describing what will appear here OR what to do next (e.g. for a professor with no courses: "Courses you teach will appear here once your department admin assigns them").
- Action is OPTIONAL — only include when there's a meaningful CTA the user can take from this screen (e.g. "Create your first announcement" on professor announcements tab). Read-only screens (student announcements list when empty) do not get an action.

- Description pattern: brief problem + clear next step ("Check your connection and try again" / "We couldn't load this course. Try again in a moment.").

## RoleThemeProvider — The Role Accent Swap

**Path:** `providers/role-theme-provider.tsx`

The provider that injects role-specific accent into a subtree. The runtime CSS-var pattern from `STACK.md` § 3 is the authoritative implementation.

**Prop signature:**
```typescript
type Role = 'admin' | 'professor' | 'student'

interface RoleThemeProviderProps {
  role: Role                         // required — current user role
  children: React.ReactNode
}
```

**Implementation contract:**
```typescript
// theme/role-theme.ts
import { vars } from 'nativewind'

export const roleThemes = {
  admin:     vars({ '--color-accent': '100 116 139' }),   // steel
  professor: vars({ '--color-accent': '204 120 92' }),    // clay
  student:   vars({ '--color-accent': '134 161 124' }),   // sage
} as const

// providers/role-theme-provider.tsx
export function RoleThemeProvider({ role, children }: RoleThemeProviderProps) {
  return <View style={roleThemes[role]} className="flex-1">{children}</View>
}
```

**How children consume the active accent:**

| Pattern | Consumer code |
|---------|---------------|
| Tailwind class (recommended) | `className="bg-accent text-white"` (already wired in `tailwind.config.js`) |
| Inline style (rare) | `style={{ color: 'rgb(var(--color-accent))' }}` |
| useRole hook (logic, not styling) | `const { role } = useAuth()` — for branching, not for color |

**Tokens that swap:** ONLY `--color-accent`. All other tokens (canvas, surface, fg-primary, border-subtle, semantic colors) are role-independent and live in `global.css` `:root`.

**Where the provider is mounted:** In each role's route group layout (`app/(admin)/_layout.tsx`, `app/(professor)/_layout.tsx`, `app/(student)/_layout.tsx`) wrapping the entire role's route tree. NOT in the root layout (because root layout renders sign-in screen, which has no role yet).

**Verification (Phase 2 success criterion 2):** A sample screen rendered three times — once inside `<RoleThemeProvider role="admin">`, once `professor`, once `student` — must show the correct accent color in each render. Phase 2 plan should include this as the visual smoke test.

**`global.css` contract for default tokens:**
```css
:root {
  --color-canvas: 250 249 245;
  --color-surface: 245 242 235;
  --color-surface-elevated: 255 255 255;
  --color-fg-primary: 42 38 34;
  --color-fg-muted: 122 115 106;
  --color-border-subtle: 232 226 213;
  --color-accent: 134 161 124;        /* default = student sage; overridden by RoleThemeProvider */
  --color-destructive: 180 84 71;
  --color-success: 94 138 96;
  --color-warning: 196 147 85;
}
```

**`tailwind.config.js` — extend `colors` to expose every token as a Tailwind class:**
The current config (`accent`, `canvas` only) is a STARTING POINT. Phase 2 extends it to map every token above to its Tailwind class (`bg-surface`, `text-fg-primary`, `border-border-subtle`, etc.) using the `rgb(var(--color-X) / <alpha-value>)` pattern.

## QueryClient Configuration

**Path:** `providers/query-provider.tsx`

**Required defaults (from Phase 2 success criterion 4):**

```typescript
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 2,         // 2 minutes — REQUIRED by success criterion 4
      gcTime: 1000 * 60 * 5,            // 5 minutes — REQUIRED by success criterion 4
      retry: 2,                          // 2 retries on transient failure (network blip)
      retryDelay: (attempt) => Math.min(1000 * 2 ** attempt, 8000),  // exponential backoff capped at 8s
      refetchOnWindowFocus: false,      // RN: window focus is meaningless; use focus event from React Native AppState instead
      refetchOnReconnect: true,         // when network comes back, refetch — important for mobile
      refetchOnMount: true,             // refetch when a component mounts and data is stale
    },
    mutations: {
      retry: 0,                          // mutations are user-initiated; do NOT auto-retry (avoid double-creates)
    },
  },
})

export function QueryProvider({ children }: { children: React.ReactNode }) {
  return <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>
}
```

**App focus integration (the RN equivalent of `refetchOnWindowFocus`):**

```typescript
// In root _layout.tsx, alongside QueryProvider
import { AppState, Platform } from 'react-native'
import { focusManager } from '@tanstack/react-query'

function onAppStateChange(status: AppStateStatus) {
  if (Platform.OS !== 'web') {
    focusManager.setFocused(status === 'active')
  }
}

useEffect(() => {
  const sub = AppState.addEventListener('change', onAppStateChange)
  return () => sub.remove()
}, [])
```

This pattern (from `STACK.md` source: TanStack Query React Native docs) gives the same UX as web's `refetchOnWindowFocus: true` — when the user returns to the app after backgrounding it, queries refetch.

**Tab-switch caching behavior (success criterion 4):** With `staleTime: 2 min`, switching to a tab with cached data within the staleness window shows data instantly with no spinner — useEffect on the consuming screen sees `data` already, `isPending` is false. This is the verification target.

**Where mounted:** Root `_layout.tsx`, OUTSIDE `RoleThemeProvider` (one global QueryClient for the whole app, regardless of role). Order of providers (outer → inner): `<SafeAreaProvider>` → `<QueryProvider>` → `<AuthProvider>` (Phase 3) → `<RoleThemeProvider role={role}>` (within role groups) → screens.

## EmptyState / Skeleton / ErrorView Usage Convention

This is the **downstream contract** for Phases 4-8. Every screen that fetches data via TanStack Query follows this exact pattern:

```typescript
function MyListScreen() {
  const { data, isPending, isError, error, refetch } = useMyQuery()

  if (isPending) {
    return <SkeletonListRow /> × 5 (or appropriate skeleton preset)
  }
  if (isError) {
    return <ErrorView onRetry={refetch} technical={error.message} />
  }
  if (!data || data.length === 0) {
    return <EmptyState icon={Inbox} title="No items yet" />
  }
  return <FlatList data={data} renderItem={...} />
}
```

**The four-state contract (also enforced by Phase 8 audit):**
1. **Pending (no cached data)** → `<Skeleton*>` preset matching the screen's content shape
2. **Error** → `<ErrorView onRetry={refetch} />`
3. **Empty (data loaded, length 0)** → `<EmptyState icon={X} title="..." />`
4. **Success** → actual list/content

**Mutation states (create announcement, mark roadmap status, etc.):**
- Button shows `isPending={mutation.isPending}` while in flight
- On success → optimistic update or refetch
- On error → toast or inline error using `text-destructive` (NOT `<ErrorView>` — ErrorView is for whole-screen failures)

## Open Questions (for plan-phase)

These are NOT design decisions — they're plan-level decomposition questions that the planner will answer when breaking Phase 2 into plans:

1. **Single vs multi-plan decomposition:** Should Phase 2 be one fat plan ("Build the design system") or split into 3 plans (tokens + theme provider + primitives)? Recommend split: (a) tokens + global.css + tailwind extend, (b) RoleThemeProvider + QueryProvider + root layout integration, (c) the 7 primitives in parallel.
2. **Skeleton animation backend:** Reanimated shared value loop vs LinearGradient shimmer. Both work; Reanimated opacity loop is simpler and ships in 2 lines. Recommend the simpler path for the time budget.
3. **Storybook / preview screen:** Should Phase 2 ship a `/dev/preview` route that renders all 7 primitives in all 3 role themes for visual smoke-testing? STRONGLY recommend yes — it's the verification artifact for success criteria 2 and 3 in one screen.
4. **`theme/tokens.ts` shape:** Currently a stub. Plan should define whether tokens are exported as a flat const object (for runtime access in JS) or are CSS-only (declared in `global.css` and never touched from JS). Recommend hybrid: CSS vars are the source of truth; `tokens.ts` exports type-safe constants for the few cases JS needs the value (e.g. passing color to lucide-react-native `<Icon color={...} />`).
5. **Inter font weights to load:** Loading 3 weights (400, 500, 600) inflates bundle by ~250KB. We use only 400 and 600 in the contract. Plan should load only 2 weights to keep cold-start fast. (500 mentioned above as Android fallback — RN's font fallback handles this without an explicit load.)
